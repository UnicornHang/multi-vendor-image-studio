# 漫画制作 Agent 产品需求与实施方案

版本 1.0 · 2026年11月22日 · 状态 为研发评审提供的实施基线

面向个人创作者，将已有 Vue 3 与 Express 多厂商图像工作台升级为漫画制作 Agent。输入创意或故事文本，输出可编辑、可恢复、可局部修改的中文彩色漫画及整章导出文件。首发运行于本地单用户环境。

本版本采用一个总控 Agent 与受约束的工具工作流；以逐格出图、程序组版和独立中文文字层作为正式交付路线。现有图像生成接口继续复用。整页生成作为后续实验路线，待模型能力与样张评测通过后开放。

# 产品目标与边界

## 用户与核心问题

主要用户是能够提供故事构想、需要持续制作中文剧情漫画的个人创作者。用户可以不会写生图提示词，但需要能调整剧情、选择人物外形并检查最终页面。

现有工作台以单次图像请求为中心。目标产品以作品为中心，将角色、场景、剧情状态、分镜、图像和排字关联起来，解决连续页面人物漂移、台词难改、重绘牵连其他画面、任务中断丢进度等问题。

产品承诺是帮助用户完成可编辑的漫画制作流程。角色相似度和复杂动作效果取决于实际接入模型，应允许人工选择候选图和局部重绘。

## 漫画表现规范

参考为用户提供的九张竖版彩色漫画图片，其中第1、3、5、9张用于本方案的视觉分析。参考用于提炼多格页面、生活化背景、人物连续性、对白节奏及章节收束方式；不预设复制其中的人物、故事、标识或水印。

默认格式为竖版页漫、从左到右再从上到下阅读。每页默认3至5格，可切换为整页插画；特写、远景、反应镜头与少量Q版表情服务叙事。画面包含细腻人物、明确场景和统一光影。对白、旁白、拟声词与关键剧情文字均可编辑。

## 首发范围

P0必须完成：作品管理、文本故事输入、创作模式、角色参考图、场景卡、章节分页、结构化分镜、矩形版式、逐格生成、候选图选择、独立文字层、单格重绘、检查清单、任务恢复、成本限制、PNG及ZIP导出、完整项目备份和恢复。

P1扩展：不规则分格、视觉检查驱动的有限自动修复、双路线样张比较、整页草稿、长篇章节摘要、批量操作和更丰富的字体及气泡样式。

P2扩展：能力验证后的局部编辑、多参考图编排、长篇资产检索、团队协作和云部署。首发不包含多人权限、在线支付、模型训练、视频制作或自动对外发布。

P0默认一章3页、每页4格，单章最多12页、单页最多6格、主要角色最多4人。超过限制提示拆章；上限是产品保护参数，可由后续压测调整。

# 成功标准与验收口径

## 功能验收

建立一部包含两名角色、一个主要场景、三页约12格的原创样章。用户能够完成设定选择、剧本修改、分镜编辑、批量出图、台词调整及整章导出。

以下项目全部通过才可发布P0：

- 12格均可关联正确的角色、场景及镜头信息，并保留生成输入、模型、候选图和选择记录。

- 台词文本与用户确认的文字逐字一致；导出前所有溢出、缺字和缺失文字层问题必须解决或明确记录为用户接受的偏差。

- 修改一个气泡只产生文字及页面合成变化，不触发生图。

- 重绘一个分镜时，其他分镜的已选图像哈希保持不变。

- 页面刷新与服务正常重启后可继续工作，已完成任务不重复提交上游。

- 超时结果不明的请求进入待核对状态，不盲目重试导致重复计费。

- 缺失图像、过期页面、阻断级错误均不能被默认为“已完成”。

- 导出的PNG顺序正确、中文可读；备份包可在干净的数据目录中恢复出可编辑项目。

## 视觉评测

准备三段原创测试剧本，覆盖单人表情、双人对白、道具传递与昼夜切换。每段制作3页，由产品验收人员按角色可识别、服装连续、动作符合分镜、背景合理、阅读顺序、气泡无遮挡六项逐格打分。

每项采用0至2分：0为无法使用，1为可接受但需调整，2为满足要求。发布要求每项平均至少1.5分，且角色身份混淆、关键动作错误等0分项已修复。此为验收目标，不代表现有模型已达到。

## 运行指标

记录首次可阅读整章耗时、每格生成次数、人工选用率、每页重绘次数、文字修正次数、恢复成功率及预算停止次数。模型耗时与本地操作耗时分开统计。首轮样章建立基线后再制定效率改善目标。

# 用户流程与关键交互

## 新建作品

用户填写作品名、创意或正文，选择忠实改编或自由创作、画风、目标页数、阅读方向和预算。忠实改编保留事件顺序、角色关系与关键台词，新增桥接内容单独标记；自由创作允许补充情节，但先输出可编辑梗概。

点击“生成制作方案”后返回梗概、角色清单、场景清单、分页建议和调用量预估。正文、参考图内的文字属于创作素材，不作为系统指令执行。参考图分析不得改写预算、模型配置或任务权限。

## 确认设定与剧本

Agent提出角色与场景草稿，用户可直接编辑。角色参考图采用生成或上传方式，用户选定后设为标准版本。单张立绘即可进入P0流程；多视角及表情表可渐进补充。

进入批量生图前须有已选角色参考图及可用的参考图渠道；不支持参考图时显示降级说明，只允许用户主动选择文本描述模式并保留风险标记，不静默忽略参考图。

提供两种执行策略：“分阶段制作”在剧本、设定、分镜后停留待查看；“自动制作”在用户已选择预算、模型和样式后连续执行，遇到缺失必填信息、预算不足或无法修复的问题停下。每个阶段随时可编辑，无须逐次弹窗确认常规操作。

## 编辑分镜与页面

每页展示剧情目的、格子顺序和阅读动线。每格支持修改镜头、动作、表情、角色、场景、道具、台词及比例。增删分镜后重新分配布局，但保留已有图像候选，受影响格标记为待检查。

用户拖动气泡、调整大小及尾巴方向；修改台词实时排字，自动保存。更改格子比例时提示可能需要重新构图，禁止直接拉伸图像。裁切使用contain或cover，明确裁切范围，默认保留人物面部和剧情道具。

## 生成与修改

批量生成前显示分镜数、候选数、调用上限及预算估计。默认每格1个候选；用户可增加候选数量。生成中可浏览已完成格，单格失败不丢失其他结果。

选中第二页第三格后输入“女主表情冷淡一点，台词不变”，Agent展示目标、保留项和拟执行动作。明确且范围内的修改直接生成新候选，不覆盖当前已选图；用户选择后替换。存在多个同名对象且无选区时要求定位；“她”“这里”等指代不得任意跨页解析。

## 导出

导出前展示缺图、待更新、文字越界和未处理问题。正式导出要求阻断项清零；“草稿导出”可保留已知问题，清单中记录草稿状态，缺图位置显示缺图标记。

已发布导出包绑定不可变项目快照。后续修改不会改变原文件。P0提供逐页PNG、按顺序命名的PNG ZIP和可编辑项目包，不提供PDF以减少首发字体及分页复杂度。

# 信息架构与页面规格

## 作品列表

展示封面、作品名、最近编辑时间、章节数、当前任务和恢复入口。支持新建、复制、归档、导入和导出备份。删除先移入本地回收站，运行中的作品需先停止调度；共享资产未解除引用前不可物理删除。

## 漫画工作区

顶部为作品名、章节选择、保存状态、预算、生成与导出操作。

左侧为章节树与页面缩略图；显示缺图、待更新、正在生成和锁定状态。中间为可缩放页面编辑器，切换“漫画预览”“分镜脚本”“候选图比较”。右侧属性随选中对象变化：页面显示版式，分镜显示镜头与参考资产，文字显示内容、字体、形状和尾巴方向。

底部Agent区域可收起，包含对话、执行计划及任务日志。对话不能成为唯一编辑入口，所有关键对象均有表单操作。恢复运行直接调用后端已有任务，不根据聊天记录重新推断已完成工作。

## 设定库

分为角色、场景、道具和画风。角色允许固定身份、多个服装版本和标准参考图；场景保存空间布局、主要机位与时间版本。跨作品复用采用复制或显式引用，默认复制，防止修改全局角色影响旧作品。

## 任务中心与设置

任务中心展示执行阶段、完成格数、失败原因、结果待核对、重试和预算；不将未知上游进度伪装成精确百分比。

设置保留现有适配器及Agent模型配置，并新增能力验证、价格配置、数据目录、备份及默认预算。基础生图继续作为独立工具；用户可将结果“收录为角色参考”“收录为分镜候选”。

桌面优先，建议工作区宽度1280像素以上。窄屏切为单面板与抽屉，保留查看、台词编辑、任务控制及导出，复杂拖拽编辑仍以桌面为主。

# 创作能力与内容契约

## 故事规划

输入创作模式、正文、长度、已有设定及用户限制。输出StoryPlan，包含梗概、章节事件、人物关系、情绪节拍、关键台词、禁止改动内容及新增内容标记。

当要求页数无法容纳正文时，输出压缩或拆章方案；不静默省略关键事件。章节生成只读取必要的原文片段、已确认设定及前章摘要，所有摘要关联原始章节版本。

## 角色和场景一致性

角色固定字段包括年龄感、发型、瞳色、体型及标志特征；服装另建版本。场景固定字段包括空间关系、家具锚点、主色与光源。道具可记录持有人和状态。

每格拥有stateBefore和stateAfter，描述在场角色、衣着、道具归属、时间及空间位置。连续性检查比较相邻分镜的状态差异，允许有明确叙事依据的换装、转场或省略。

角色标准图选择后锁定为版本。seed仅用于复现辅助，不承诺凭固定seed保持身份一致。

## 分镜规划

每页包含pagePurpose、阅读顺序、layoutTemplate和panels。每格包含beatId、characterIds、sceneVersionId、outfitVersionIds、shot、camera、action、expression、props、dialogues、stateBefore、stateAfter及重要区域。

动作必须能在一张静态图中表达。多步行为拆格；双人对白明确左右站位、朝向和说话人，避免所有角色描述混成一个主体。

## 提示词编译

编译顺序为画风规范、固定身份、服装版本、场景、当前动作、镜头、构图保留区及负向约束。输出由确定性模板与模型辅助字段共同构成，记录编译器和提示词版本。

正式逐格路线不把台词、旁白和拟声词拼进生图描述。保留无文字约束及气泡避让区域；便签、手机、招牌的剧情文字也由文字层承担。若模型已经画出不可用伪文字，可重绘或使用支持的图像修复能力，程序文字叠加不等于能自动清除底图文字。

# 版式与中文排版

## P0版式规则

提供单幅、上下两格、三横格、大格加双小格、四格和六格等矩形模板。页面标准尺寸默认1024乘1536像素，允许配置其他尺寸；使用归一化坐标保存，不依赖屏幕缩放。

分镜区域以x、y、width、height表示，范围0至1；所有边距、格间距、边框均计入布局。模板生成确定的区域，Agent只选择模板与分配剧情，不自由产生不可验证的任意多边形。P1再增加斜切及异形格。

## 图文合成

前端用SVG渲染布局与可编辑文字；后端使用相同布局规格、字体文件和文本布局结果渲染PNG。渲染器需要统一字体测量及换行算法，不能仅依赖浏览器截图获得看似相同的输出。

图像、边框、气泡、文字及拟声词为独立层。气泡按说话人关联角色，保存尾巴目标点、形状、层级、内边距与对齐方式。人物脸部及重要道具区域作为排版避让区，自动位置可被用户覆盖。

## 中文文字规则

P0内置许可可随产品分发的中文字体，导出时检查字体可用及缺字。逐行使用真实字体度量，处理中文标点禁则、英文及数字混排、显式换行和字号下限。

自动排字先换行、再扩大气泡、再尝试移动，最后提示缩短文本；不得无限缩小字号或默默截断。旁白框、对白气泡、思考气泡及爆发气泡提供不同样式。连续气泡用order字段确定阅读顺序，不能依赖对象创建时间。

对白数据使用speakerId、text和order；旁白speakerId为空且type为narration。语义文字原文与渲染换行结果分别保存，以便校验导出没有遗漏。

# Agent架构与工具执行

## 模块划分

总控Agent理解用户目标、提出下一步及修改范围；后端工作流负责状态推进、校验、预算、持久化与工具执行。编剧、设定、分镜和视觉复盘为不同调用职责，首发不引入多个自治Agent相互协商。

工具集合包括planStory、buildCharacters、buildScenes、planPages、buildPanels、compilePrompt、generatePanel、selectCandidate、composePage、checkContinuity、reviewVisual和exportChapter。工具输入输出采用严格schema，模型只能提交受允许的对象字段及动作。

生成图像统一复用runGeneration。后台任务的AbortSignal由任务控制器管理，不再与发起请求的浏览器连接绑定；关闭页面或断开SSE不得中断后台任务。

## 执行流程

创建运行记录 → 读取版本快照 → 规划 → schema校验 → 检查前置条件和预算 → 执行工具 → 保存输出 → 检查 → 推进下一阶段。

模型JSON结构错误可进行一次受约束修复，仍失败则停在当前任务；不能因缺字段而默认通过。服务端限制页数、格数、对象归属、枚举、坐标范围和输出长度，检查引用关系有效。

用户修改在运行中只创建新版本。任务继续读取启动时快照；返回结果若基于过期输入，保存为旧版候选且标记不可自动应用。

## 检查与修复策略

确定性检查覆盖缺图、重复ID、坐标越界、文字溢出、角色引用缺失、依赖过期与必需资产缺失。语义检查覆盖角色身份、动作、场景和剧情连贯性；只有视觉模型实际收到图像时才能标为视觉检查。

P0提供检查清单及人工触发复盘，不自动连续重绘。P1允许按issue类型自动选择排字、重新合成或重绘，每格最多2轮自动修复，并受项目预算与调用上限共同限制。复杂剧情变更和被锁定对象需停下交给用户。

检查输出包含issueId、targetId、severity、category、evidence、suggestedAction和status。严重度为blocker、warning、info；用户忽略需留下理由，缺图等硬性阻断不得作为正式导出通过。

# 任务状态与恢复机制

## 任务状态

queued等待调度；running执行中；waiting_user等待选择或修正；paused在安全点暂停；retry_wait等待可重试错误退避；reconciling结果待核对；succeeded成功；failed失败；cancelled取消。

run另保存pause_requested与cancel_requested标记。暂停停止新调用，允许在途调用结束并保存；取消停止新调用并尽力中止在途请求，但不保证上游停止计费。已返回资产始终保留，不自动应用被取消任务的结果。

429且明确未执行时按上游退避提示重试；一般可重试错误最多2次重试，采用指数退避与抖动。400、鉴权失败、额度不足、审核拒绝不自动重试。可能已经成功的超时、网络断开或未知5xx，若无上游幂等或结果查询支持，一律进入reconciling，先核对再由用户决定新增调用。

## 持久化执行

每个工具调用单独为task，记录inputHash、dependencyVersions、idempotencyKey、attempt、upstreamRequestId、heartbeat、leaseUntil和结果。

worker通过数据库事务获取租约并限制同一任务被重复领取。进程重启后扫描过期running任务：本地纯计算任务可重做；外部请求先查询结果或进入待核对，不假定上游没有执行。上游幂等能力存在时使用同一键恢复。

P0采用单进程持久化队列，默认同一渠道图像并发为1，全局最多2个图像调用，文本规划并发为1；参数可配置。任务相互依赖用有向无环图保存。单格失败只阻断其所在页合成与相关最终导出，不阻断无依赖页面。

## 事件与前端恢复

通过SSE发送单调递增eventId及runId、taskId、type、stage、message和时间。重连使用Last-Event-ID补发；超出保留范围时拉取完整任务快照。SSE仅订阅，任务控制使用独立POST接口。前端进度按已完成任务数显示，运行中标注等待上游。

# 数据模型与版本规则

## 核心实体

Project保存id、name、creationMode、styleVersionId、readingDirection、canvasSpec、budgetPolicy、schemaVersion与revision。

Chapter保存projectId、sourceText、storyPlanVersion、synopsis及pageIds。Page保存chapterId、order、purpose、layoutVersion及panelIds。Panel保存pageId、order、beatId、角色场景及服装版本引用、镜头动作、状态差异、imageVersions、selectedImageId、textLayers、locked和revision。

Character、Outfit、Scene、Prop和Style均保存稳定ID及不可变版本。Character另关联标准参考Asset。TextLayer保存type、speakerId、text、order、bbox、shape、tail、font及revision。

Asset保存id、内容哈希、相对存储位置、mime、width、height、bytes、来源和引用计数。GenerationAttempt保存模型及渠道标识、提示词版本、输入哈希、参考资产、输出资产、耗时、已知费用和价格依据。

Run保存目标、执行策略、快照、预算与整体状态；Task保存依赖、尝试与状态；ReviewIssue保存问题；Export保存快照、格式、资产和校验结果。所有实体保存createdAt和updatedAt，不在这些记录中存明文密钥。

## 状态分离

内容状态使用draft、ready、stale；审核状态使用unchecked、passed、needs_changes、waived；任务状态独立保存。未运行检查不能标为passed，选中一张图也不代表该页已通过检查。

对文本和结构变更增加revision，更新采用expectedRevision进行乐观锁校验。并发冲突返回409，前端保留未保存输入并提供重新加载或合并。

## 依赖失效

依赖链为设定版本和剧本版本 → 分镜及提示词 → 图像候选 → 页面合成 → 导出快照。

修改台词仅使文字布局和页面合成过期。修改动作使当前格图像过期。修改角色标准版本提示受影响分镜，默认仅对未来新生成生效；用户选择应用到已有页面后才把相关图像标为stale。

锁定阻止自动覆盖，不阻止依赖失效提示。重绘保存新候选，选中后才替换展示版本。恢复旧版本创建新的当前revision，历史保留。已完成导出保持不可变。

# 存储与资产管理

P0采用SQLite保存结构化对象、任务、事件和版本；图片保存到本地DATA_DIR下按内容哈希组织的assets目录。SQLite访问通过统一repository层，worker与API共享事务规则。现有JSON历史和角色数据只作为兼容源，不继续承担新队列的并发写入。

上游返回data URL时解码后校验并落盘；返回远程URL时及时下载并验证类型、大小与尺寸，落盘成功才将图像任务标为成功。下载失败保留上游结果进入asset_pending子状态，优先重试下载，不重新生图。禁止以临时链接作为唯一正式资产。

P0默认单图输入不超过20MB，支持JPEG、PNG、WebP；图像解码还需限制像素总量。所有外部下载验证重定向每一跳和解析后的目标地址，禁止访问本机、内网及云元数据地址；参考素材从受控assetId解析，不接受模型自行构造的文件路径。

项目备份包包含manifest.json、内容快照、版本引用、必要图片及字体信息，不包含密钥。导入校验schemaVersion、引用完整性、哈希、总大小及压缩路径，不允许路径穿越。备份期间绑定一致数据库快照及同版本资产。

删除采用软删除与延迟回收，只有无活动引用且不受保留备份依赖的资产可以清理。磁盘不足停止新增调用，已获得结果优先保存并提示释放空间。

# 接口契约

新接口使用/api/comics前缀，现有/api/generate、/v1/images/generations及/api/agent接口保持兼容。

## 作品与内容

POST /api/comics/projects：创建作品，返回201及项目对象。
GET /api/comics/projects：分页列出作品。
GET /api/comics/projects/:id：读取作品摘要、revision和章节。
PATCH /api/comics/projects/:id：带expectedRevision更新作品。
POST /api/comics/projects/:id/chapters：创建章节。
GET /api/comics/chapters/:id：读取章节及页面。
PATCH /api/comics/pages/:id：修改布局或页面属性。
PATCH /api/comics/panels/:id：修改分镜结构。
PATCH /api/comics/text-layers/:id：修改台词、位置与样式。
POST /api/comics/assets：上传素材并返回assetId。
GET /api/comics/assets/:id/content：按项目访问规则返回本地资产。

角色、场景、道具与画风采用项目下/assets-library资源，type区分实体，版本独立创建；不得用同一ID静默覆盖已被历史引用的版本。

## 运行与修改

POST /api/comics/projects/:id/runs：创建后台运行。请求含target、action、expectedRevision、executionPolicy和budgetPolicy，返回202及runId。action枚举为plan_story、prepare_assets、plan_pages、render_panels、compose、review、export；target必须属于项目。

POST /api/comics/projects/:id/commands：解析自然语言修改，输入text、selection和expectedRevision。无歧义则创建运行；有歧义返回200及needs_input和候选目标，不执行付费调用。

GET /api/comics/runs/:id：读取快照。
GET /api/comics/runs/:id/events：订阅SSE。
POST /api/comics/runs/:id/actions：动作限定pause、resume或cancel。
POST /api/comics/tasks/:id/retry：显式重试，未知上游结果必须带核对决定。
POST /api/comics/panels/:id/select-candidate：选择候选，带expectedRevision。
POST /api/comics/projects/:id/exports：创建导出任务，包含chapterIds、format和draft标志。
POST /api/comics/projects/:id/backups：创建完整备份。
POST /api/comics/imports：校验并导入备份，返回新projectId。

所有创建运行、重试和导出请求支持Idempotency-Key。同键同内容返回原任务；同键不同内容返回409。同步校验失败不创建任务；上游错误在任务记录中返回。

## 通用响应

成功返回data、requestId和相关revision；错误返回error.code、message、retryable、field、details与requestId。标准状态码包括400参数错误、404对象不存在、409版本或幂等冲突、413素材过大、422前置条件不满足、429本地限流、503服务暂不可用。

关键错误码包括capability_missing、reference_required、revision_conflict、budget_exhausted、price_unknown、upstream_outcome_unknown、asset_persist_failed、text_overflow与export_blocked。前端按错误类型给出下一步，不只展示原始异常。

# 模型适配与费用控制

## 能力注册

能力按渠道、模式和模型组合记录，并区分声明状态与验证状态。包含textToImage、characterReference、styleReference、multiReference、imageEdit、maskEdit、visionReview、seed、supportedRatios和maxReferenceImages。

状态为unknown、declared、verified或unsupported；保存验证时间、适配器版本和样例结果。连通性测试不能替代参考图或局部编辑测试。P0不依赖图像编辑能力，所谓“单格重绘”默认是重新生成该格。

路由先满足必需能力，再按用户指定渠道、费用与近期可用性选取。切换模型不能绕过用户配置的渠道范围，不能静默丢弃角色参考图；发生降级时先停留在可选方案。渠道自动重试只在已确认未成功且不会重复计费时执行。

## 预算

预算同时设置最大新增图像调用次数、文本调用次数和可选金额。每次调用前原子预留最坏已知费用，成功后结算，失败按上游已知计费规则记录；结果不明时保留费用预留。

价格包含币种、单位、来源、适用模型与更新时间。用户可手动填写。没有可信价格时显示金额未知，禁用声称具有金额保障的预算模式，使用调用次数作为硬上限。

初次预算估计为角色参考调用加分镜数乘每格候选数，再加文本规划、视觉复盘和允许修复的上限。并发任务共享同一预算预留，防止同时越限。上游真实账单可能与估算不同，界面区分估算、已知计费和待核对金额。

达到阈值进入waiting_user并停止新调用；用户可增加预算或缩小范围后恢复。不能因为切换模型或修复任务重新生成run而重置作品级上限。

server/src/services/llm.js保留文本及视觉调用。现有fillForm、buildStoryboard、makeCharacters和refineImage先作为兼容工具保留；新工作流调用新的结构化契约。原有生图、历史、渠道配置和用量功能持续可用。

建议增加services/comics下的orchestrator、planner、promptCompiler、layout、typesetter、reviewer、assetStore及exporter；新增repositories/comics与jobs目录，分别承载SQLite访问和持久化worker。新路由统一挂到routes/comics。

shared/comics下保存schema、版本枚举、版式模板和能力契约。前后端共用字段定义及验证规则，模型输出必须经过服务端校验，不只做字符串裁切。

原routes/agent.js的断连中止逻辑仅用于现有同步请求。新异步路由返回任务ID后脱离请求生命周期，不能直接复制abortOnClose到后台工作流。

useAgent.js中的applyPanel目前会把dialogue及sfx追加到detail，新工作流改为写入TextLayer。现有旧助手可兼容保留，但从旧分镜导入漫画项目时必须拆出文字层并展示预览。

角色存储从characters.json升级为版本化实体。迁移前备份，保留原ID、createdAt和updatedAt；新系统不得沿用现有60条截断策略，不能因新增角色静默丢弃旧数据。迁移可重复执行，通过来源ID避免重复导入；失败回滚事务并保持旧文件可用。

## 验证入口

保留现有server测试与web配置解析测试。新增任务恢复、预算原子预留、幂等请求、版本冲突、文字布局、导出和备份恢复测试。前端继续使用现有构建命令验证集成。实际模型验收独立于自动化测试执行，并记录模型及渠道配置版本。

# 非功能要求与运行保障

本地元数据读取及普通编辑保存目标为P95低于500毫秒，统计不含上游模型耗时；保存成功提示必须发生在持久化提交后。前端输入自动保存防抖默认800毫秒，切页前立即提交，失败保留编辑缓存并明确显示未保存。

P0性能基准为1个活动生产任务、12页每页6格及200个图像资产，测试环境记录操作系统、CPU、内存与磁盘类型。最终验收以该规模下交互不阻塞、进程重启可恢复为准，不对外部模型生成时延设固定承诺。

密钥保留在服务端配置，不写入项目包、SSE、提示词、日志或返回的请求快照。兼容旧页面配置时后台任务只引用credentialRef，不把密钥固化到任务数据库。日志记录requestId、runId、taskId、错误类型、耗时、token及图像数量；正文和图片默认不进入诊断日志。

单用户服务默认只监听本机；云端或多人部署需新增认证、授权和隔离后才能开放。素材及模型输出视为不可信内容，限制文件路径、工具白名单、响应大小与调用次数。界面导入文本不得触发任意网络访问或执行脚本。

提供数据目录备份说明、数据库迁移记录、存储用量和诊断导出。诊断包默认脱敏。上线前验证中途断电等效的强制进程退出与恢复，不能仅验证正常停止。

# 研发阶段与工作包

以下为工作量规划假设：两名熟悉现有代码的全栈研发、一名兼职产品设计与测试，共六个迭代，每个迭代约一周；实际工期在第一阶段技术样机后重估，不作为未经评估的交付承诺。

## 阶段一 技术样机与能力验证

交付：选定渠道完成同一角色跨三页约12格样张，中文排版及后端PNG合成样机；验证参考图是否真正生效，确认字体与渲染方案。

退出条件：可识别角色、双人构图及文字层达到样张可用标准，无法达到时调整模型或缩小风格范围，先不投入全量编辑器。由研发负责调用验证，产品负责视觉评测。

## 阶段二 作品数据与任务底座

交付：SQLite迁移、资产落盘、作品CRUD、任务租约、幂等、事件及预算预留。完成旧角色只读兼容与可回滚迁移。

退出条件：模拟进程退出可恢复，断开页面任务继续，重复提交不产生重复上游请求。

## 阶段三 故事设定与分镜流程

交付：故事模式、版本化角色与场景、章节分页、分镜契约、剧情状态和提示词编译。

退出条件：三页剧本可编辑，所有分镜引用完整，台词从图像描述中分离，严格模式可追踪新增内容。

## 阶段四 编辑器与批量出图

交付：页面模板、选择与拖拽、气泡编辑、候选比较、单格重绘、锁定及任务控制。

退出条件：调整台词不调用模型；单格替换不改变其他格；刷新保持项目进度。

## 阶段五 检查导出与恢复

交付：检查清单、人工复盘、正式及草稿导出、ZIP项目备份和导入恢复。

退出条件：真实样章完成端到端生产，导出图像与编辑预览一致，备份可在空目录恢复。

## 阶段六 回归与首发

交付：三组测试剧本的评测记录、错误路径覆盖、迁移回滚说明、使用说明和已知限制。

退出条件：所有P0验收通过，无数据丢失、重复计费自动重试、阻断导出失效等高优先级缺陷。之后进入P1整页草稿及有限自动修复。

# 测试场景与发布门槛

## 必测用户场景

T01从一句原创故事创建三页漫画，完成设定、分镜、出图与导出，导出的页序与文本正确。

T02忠实改编含关键台词的原文，关键事件没有静默删除，新增桥接可查看。

T03修改台词并拖动气泡，图像调用数保持不变，最终PNG文字完整且无溢出。

T04重绘第二页第三格，其他已选图哈希不变，旧候选可以重新选择。

T05生成途中关闭页面并重开，展示相同runId及已完成任务，在途调用不中断。

T06强制终止后端后重启，已落盘结果不重复生成，结果不明任务进入reconciling。

T07两个并发分镜争用最后一次调用额度，仅一个获准提交，其余等待预算。

T08缺少参考图能力时，不静默降级；用户选择文本模式后在任务及评测记录标记降级。

T09生成期间修改分镜，新结果保存为旧版候选，不覆盖新revision。

T10模拟临时链接失效与下载失败，任务只重试资产获取；拿不到资产时不宣称出图成功。

T11长中文、标点开头、混合英文、缺字字体和最大气泡边界，均产生正确布局或明确阻断。

T12导出包恢复至空数据目录，角色版本、已选图、台词位置和页序一致且不含密钥。

T13连续重复Idempotency-Key，返回同一个任务；请求体变化返回409。

T14素材下载发生内网重定向、非法格式或超大像素，下载被拒绝且不影响其他已保存任务。

T15取消运行时已有上游返回，保存资产但不应用取消后的结果，费用显示已知或待核对。

## 发布门槛

必须通过自动化单元及集成测试、前端构建、人工编辑器验收及真实上游样章评测。付费上游测试使用独立调用上限，不能将mock通过当作视觉质量通过。

发布包包含迁移版本、数据备份和回滚操作。结构迁移先备份，使用事务提交；回滚应用版本时恢复相匹配的数据快照，不让旧代码直接写入新schema。

# 风险与实施决策

角色漂移的首要应对是先完成样张验证、固定参考版本与人工选图；文字描述和seed都不能替代实测。双人动作失败时优先重写为明确的单步镜头，必要时拆格。

逐格路线的主要风险是页面光影和空间不统一，通过场景版本、镜头状态与整页检查约束。整页路线的主要风险是可编辑性与文字准确性，因此P0正式交付不依赖整页模型直接生成可读中文。

编辑器复杂度通过矩形模板与有限气泡样式控制；不规则分格、自由变形与任意矢量绘制放在后续阶段。SQLite及本地存储服务首发单用户规模，未来多人部署保留repository接口迁移空间。

默认决策已确定：本地单用户、中文竖版页漫、逐格生产、独立文字层、SQLite加本地资产、持久化任务与SSE、P0人工触发复盘、P1有限自动修复。模型、具体字体与渲染库通过阶段一样机验证选定，不在未验证前锁死。

产品负责人负责故事质量与验收口径；研发负责数据、任务和渲染实现；测试负责异常与恢复验证。角色可以由同一人兼任，但每阶段退出条件都应有明确签收记录。
